# NexoraDB v0.2.0

NexoraDB 0.2.0 focuses on atomic document mutations, index correctness, and
measurable C++ query performance.

## Highlights

- Atomic document, index, unique-constraint, and collection-counter mutations.
- Transaction conflict/timeout propagation without partial-success responses.
- Bounded and resumable online index builds with Building, Ready, and Failed states.
- Versioned v2 physical index keys with stable index IDs and binary-safe encoding.
- Order-preserving integer, floating-point, Boolean, and string index encoding.
- Compound indexes, prefix matching, transactional unique enforcement, and
  schema-level unique-index coordination.
- Equality/range index planning for `FindMany`, `Count`, and `Exists`.
- `ExplainPlan` output with scan type, selected index, and actual scan counts.
- Snapshot-backed keyset pagination for a stable multi-request traversal.
- Standalone deterministic native C++ benchmarks with p50/p95/p99 metrics.
- Debug, Release, ASan, UBSan, TSan, and benchmark CMake presets.

## Compatibility notes

- Existing legacy v1 physical indexes must be migrated using
  `RebuildIndexes` / `rebuild_indexes` before relying on v2 query planning.
- Pagination continuation tokens refer to an in-process RocksDB snapshot. They
  expire after five minutes and are invalid after process restart or when sent
  to another server process.
- Python wheels target CPython 3.10 on Linux, as declared by the package metadata.

## Verification target

Before publishing, run the release validation, Release C++ tests, sanitizer
tests, Python tests, wheel metadata checks, and the 100K native benchmark. The
exact commands are documented in `docs/cpp/BUILD_TEST_BENCHMARK.md`.
