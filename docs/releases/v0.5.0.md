# NexoraDB 0.5.0 — correctness and bounded resource execution

Prepared locally on 2026-10-31. **The wheel is built and clean-install validated;
no tag, upload or public release has been performed.** The user selected a
limited experimental candidate based on the accepted 10M profile and deferred
100M. RES-004/005 research remains open, without comparative performance claims.

## Changes

- Index format v3, canonical numeric equality/uniqueness, reader fences and
  [offline copy migration](../cpp/INDEX_V3_MIGRATION_FA.md).
- Read Committed transactions, opt-in point locking, structured conflict codes,
  FK mutation/revalidation and reverse RESTRICT guards, immutable document ID.
  [Isolation and constraints](../cpp/ISOLATION_CONSTRAINTS_FA.md).
- Document/index/counter/WAL/ACK fault and corruption coverage.
  [Failure matrix](../cpp/FAILURE_RECOVERY_MATRIX_FA.md).
- Memory ownership telemetry, allocator-retention diagnostics, shared admission
  and [bounded scan/sort/group/spill APIs](../cpp/RESOURCE_ADMISSION_SPILL_FA.md).
- Per-app execution limits, protected small-query/maintenance shares, bounded
  priority bypass, native cancellation and ordered shutdown. Matcher-exception
  snapshot cleanup was fixed. [Contract](../cpp/ADMISSION_SHUTDOWN_FA.md).

## Upgrade and platform

**Back up and follow the offline copy-migration procedure before opening an
older indexed store.** This is not a general in-place index upgrade. Preserve
the original store and a compatible old reader for rollback. No user store was
migrated during preparation. FK-orphaning mutations previously accepted may now
be rejected; referenced schema/index DDL requires removing the FK first.

The wheel targets **CPython 3.10, Linux x86_64, manylinux_2_35** (glibc 2.35+).
Windows use is through compatible WSL Linux; this is not a native Windows wheel.
No macOS, other Python ABI or older-glibc artifact is included.

## Known limits and dependency audit

`npm audit --omit=dev` reports zero findings. The full locked development tree
reports 12 moderate findings through eslint/minimatch tooling, zero high/critical;
the existing high/critical CI gate passes. Those Node tools are not shipped in
the Python wheel. The audit is retained; development dependencies are not claimed
vulnerability-free. No force-upgrade or lint downgrade hid those findings.

The first local wheel attempt used an old build-tools setuptools and failed;
the isolated pyproject build succeeded. Both logs are retained.

This remains experimental software. There is no 100M or graph-capacity acceptance,
general leak-free/hard-RSS guarantee, replication, power-loss simulation or atomic
document-plus-graph transaction. ORDER BY/GROUP BY grammar and general executor
certification remain open. RES-004/005 remain open without superiority claims.
[100M planning](../cpp/MEMORY_100M_PLAN_FA.md) is deferred and unexecuted.
