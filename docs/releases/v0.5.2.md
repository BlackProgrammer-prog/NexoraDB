# NexoraDB 0.5.2 — unified query workspaces and terminal hardening

## Changes

- Add a CodeMirror NexoraQL editor to the React console: multiline input,
  highlighting, debounced server diagnostics, located error markers and
  Ctrl/Cmd+Enter execution. Parameters and diagnostics use the actual server
  parser rather than a separate SQL implementation.
- Extend Streaming and server-cursor results to supported scripts, metadata,
  graph operations and mutation programs. Statement records and execution
  receipts distinguish failures and committed/rolled-back work.
- Add bounded native LOOKUP JOIN iteration, including up to eight distinct
  chained targets. A SELECT and its lookup targets retain the same RocksDB
  snapshot across pages. Separate SELECT statements use separate snapshots.
  Existing first-match lookup semantics are preserved; this is not relational
  fan-out or a new general-purpose SQL JOIN dialect.
- Complete side-effecting programs before result delivery, with private,
  disk-bounded result spools and durable Idempotency-Key reservations. Expired
  results or uncertain outcomes never silently reexecute writes. Request-status
  endpoints and the Python driver expose recorded receipts.
- Bring the Textual TUI onto the same query APIs: multiline highlighting,
  diagnostics, JSON parameters, bounded history, Streaming, cursor navigation,
  cancellation and request-status lookup. F5 runs, F6 stops/closes and F7 fetches
  the next cursor page; Enter adds a newline.
- Optimize terminal monitoring with async I/O, coalesced updates, keyed connection
  rows, bounded histories and paused rendering in inactive tabs. Unavailable or
  health-only data is explicitly distinguished from native database metrics.
- Harden terminal credentials and output: masked one-time token presentation,
  temporary reveal, guarded clipboard access, bounded literal output, terminal
  control filtering, screen-owned cancellation and duplicate-operation guards.
  Graph identifiers are validated and node arguments are bound, not interpolated.
- Harden monitoring transport with bounded WebSocket messages, rejected binary
  attachments/redirects and preserved reverse-proxy path prefixes. Update minimum
  security versions for AnyIO, Certifi, Cryptography and the build toolchain;
  declare aiohttp for the async monitoring client.

## Upgrade and deployment

0.5.2 remains a **CPython 3.10, Linux x86-64** release. The repaired wheel targets
`manylinux_2_35_x86_64`. Replace the complete installed package and restart the
service; do not hot-swap a native extension in a running process. Back up the
database, graph state and request journals before upgrading. Storage/index
encoding is unchanged from 0.5.1; older storage migrations still follow the
[0.5.0 precautions](v0.5.0.md).

The new query journal is `query_requests.sqlite3` under the configured database
directory. Keep it with the database's persistent state and backups. Do not
delete pending reservations to retry uncertain writes. Prepared result files
and live cursor IDs are process-local and expire; multi-worker deployments need
sticky routing. A restart does not provide exactly-once crash atomicity between
RocksDB and the separate journal. Reconcile ambiguous writes before a new run.

Cursor/Streaming side-effecting programs require an Idempotency-Key. The web and
terminal workspaces create and display one per explicit run. Buffered execution
retains its existing contract and does not add replay protection. Cancelling
delivery does not undo writes already committed.

Server limits remain explicit: 256 statements, up to eight distinct lookup
targets, bounded pages/frames, 30-second idle and 120-second managed-cursor
lifetime. Transactional SELECT/UPDATE/DELETE require an exact `_id` predicate;
transactional JOIN and transactional graph projection remain unsupported.
Graph-enabled write sessions reject unsupported transaction writes in preflight.
The default configured request deadline can be shorter than the cursor ceiling.

Use `npm ci` with Node.js 24 when rebuilding the dashboard. Production services
should serve the bundled assets and use HTTPS/WSS for remote connections.
Terminal-created application tokens now default to a one-day expiry and remain
masked until explicitly revealed. Ctrl+Q quits the console.

## Known security limitation

The optional PyMongo/BSON/benchmark environment can still install `dnspython
2.8.0`, affected by
[GHSA-45c3-73f7-pv4m](https://github.com/rthalley/dnspython/security/advisories/GHSA-45c3-73f7-pv4m).
The patched 2.9.0 requires Python >=3.11, which the current native-wheel ABI does
not support. This advisory is not suppressed. The TUI does not use dnspython,
but optional MongoDB SRV/DNS clients must not be assumed protected. A supported
backport or a separate Python/native ABI migration is needed for that dependency.

Existing experimental-scale/platform limitations remain applicable. The release
does not claim unrestricted SQL support or industrial security certification.

## Validation and publication

[Local candidate validation](validation-v0.5.2.md) records the actual build,
tests, clean-install checks, artifact hashes and remaining audit findings.

Commit and push the reviewed changes, merge them into `main`, then create the
`v0.5.2` tag from that merged commit. Publishing its GitHub Release triggers the
PyPI workflow. The workflow rejects a mismatched version or a release commit
outside `main` and rebuilds the wheel from the release source. Local preparation
does not create a tag, commit, push, GitHub Release or public package upload.
