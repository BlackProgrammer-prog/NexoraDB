# NexoraDB 0.4.1 — PyMongo security dependency update

Prepared 2026-10-26. This source update does not publish a release or dismiss alerts.

## Development update — 2026-10-30 (not a published artifact)

The current working tree additionally introduces index format v3 (`NXI3`/`idx3`)
and a generation-3 reader fence. Numeric equality and uniqueness now share
canonical int/double/zero semantics. Numeric range queries still use a correct
full scan; this update does not claim globally ordered mixed-number index keys.
Existing indexed stores require an offline copy migration; do not point this
native build at an old indexed store expecting an automatic in-place upgrade.
See [migration procedure and limitations](../cpp/INDEX_V3_MIGRATION_FA.md).

The dependency-only validation and wheel listed below are historical evidence
for the October 26 candidate, **not validation of the current storage changes**.
Rebuild, clean-install and release validation are required for a new candidate.
Do not overwrite a previously published 0.4.1 artifact; choose the next release
version before publishing if that version is already public. No version bump,
publication or migration of user databases has been performed here.

The development tree also documents Read Committed transactions (not general
Serializable isolation), adds opt-in `find_by_id_tx(..., for_update=True)` point
locking and structured transaction conflict/timeout/deadlock error codes.
Foreign-key mutations now use a conservative store-wide transactional guard,
revalidation and reverse RESTRICT checks. Parent deletion/referenced-value
changes may now be rejected where the previous code could leave orphans;
referenced collection/index DDL requires explicitly removing the FK first.
Installing an FK audits existing children and can be expensive on large stores.
`_id` mutations are rejected. The no-FK ingestion path is not routed through the
FK guard. See [isolation/constraints](../cpp/ISOLATION_CONSTRAINTS_FA.md) and the
[independent bounded reference model](../cpp/REFERENCE_MODEL_FA.md).

## Security changes

- Benchmark PyMongo pin: `4.10.1` → `4.18.3`.
- Binary-client extra, performance-test dependencies and Python API CI now require
  `pymongo>=4.18.3,<5`, preventing fresh resolution to the affected versions.
- All product version metadata and current README links are synchronized to 0.4.1.

The requested alerts are fixed upstream in the following releases:

| Upstream issue | Description | Fixed upstream |
|---|---|---|
| PYTHON-5986 / CVE-2026-96748 | Percent-encoded host delimiter injection | 4.18.2 |
| PYTHON-5996 / CVE-2026-96749 | Signed BSON encoding-size overflow | 4.18.2 |
| PYTHON-5994 / CVE-2026-88029 | GridFS delete identifier interpreted as a predicate | 4.18.1 |
| PYTHON-5990 / CVE-2026-96747 | KMS endpoint interpreted as a Unix socket path | 4.18.2 |

We select 4.18.3 because it additionally fixes CVE-2026-106435. Sources:
[MongoDB release notes](https://www.mongodb.com/docs/languages/python/pymongo-driver/current/reference/release-notes/)
and [PyMongo 4.18.3](https://github.com/mongodb/mongo-python-driver/releases/tag/4.18.3).
These are fixes to an external dependency; NexoraDB does not maintain a fork of it.

## Upgrade

For the benchmark environment:

```bash
nexora-scale-lab/.venv/bin/python -m pip install -r nexora-scale-lab/requirements.txt
```

For an installed binary-client extra, after publication:

```bash
python -m pip install --upgrade 'NexoraDataBase[binary]==0.4.1'
```

An existing virtual environment or downstream lockfile is not upgraded by changing
the source requirement alone. Upgrade its installed dependency and regenerate its
lockfile as appropriate. The base package still makes PyMongo optional; benchmark
and BSON client paths use it. Native storage-format versions are unchanged.

## Validation scope

Regressions cover the installed security floor, rejected encoded-host injection,
exact GridFS delete filters and BSON roundtrip, alongside existing binary API and
real small-dataset adapter/protocol tests. The multi-GiB encoder-overflow trigger
and live encrypted-KMS attack are not executed locally; those fixes rely on the
upstream patched release. Historical performance results remain unchanged; new
measurements must record the new driver version. No large benchmark is required
to validate this dependency update.

The experimental document/graph/security limitations documented for 0.4.0 remain
applicable. Dependabot status is only known after GitHub scans the merged default
branch; no alert has been dismissed locally.
