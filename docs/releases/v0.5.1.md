# NexoraDB 0.5.1 — console security, performance and regression coverage

Prepared on 2026-11-03.

## Changes

- Override transitive `minimatch` dependencies to `^11.0.1` and regenerate the
  frontend lockfile to address Dependabot alert #27, globparts amplification
  denial of service ([GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249)).
  The override covers ESLint and typescript-eslint dependency paths whose
  declared ranges otherwise retain minimatch 10.x.
- Synchronize Python, CMake, vcpkg, frontend and current README release metadata
  to 0.5.1.
- Fix all 10 frontend lint errors: initialize editor forms per open session,
  derive default collection selections, separate the auth hook from the
  provider, and reset token/monitoring state without synchronous effect updates.
  Token fetch cleanup ignores obsolete requests; socket cleanup removes listeners.
- Review and improve console performance and browser security: lazy route/graph
  loading, bounded rendering, request cancellation, memory-only admin credentials,
  browser security headers and live server-side admin authorization checks.
  [Review, validation and deployment requirements](../FRONTEND_REVIEW_0.5.1.md).
- Add 98 frontend development regression cases with watch/CI commands; reject
  scalar JSON in editors, handle synchronous loader failures and guard invalid
  monitoring timestamps. [Test guide](../../frontend/TESTING.md).

## Upgrade

Use `npm ci` in `frontend` to install the patched locked dependency tree.
Node.js 24 is used by the release workflow.

Admin sessions now live only in tab memory: reloading the console requires
signing in again. The production API defaults to the console's own origin;
explicit remote API/socket endpoints must use HTTPS. Console requests and
responses have size/time budgets; see the review for exact limits.

This patch changes development dependencies, dashboard state handling and release metadata. Storage and
index formats are unchanged from 0.5.0. When upgrading from older releases,
follow the backup and offline migration precautions in the
[0.5.0 release notes](v0.5.0.md).

The platform and experimental-scale limitations documented for 0.5.0 still
apply. The native module and wheel have been rebuilt as 0.5.1 and clean-install
validated locally. No public upload, tag or remote CI run has been performed.
[Final candidate validation](validation-v0.5.1.md).
